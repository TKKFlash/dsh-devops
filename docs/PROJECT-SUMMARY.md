# dsh-devops 项目总结

> 从设计调研到 v0.2.0 交付的完整记录，用于整理周报。
> 时间跨度：2026-11-04 ~ 2026-11-05　｜　仓库：https://github.com/TKKFlash/dsh-devops

---

## 一、项目定位

**一句话**：为 DeepSeek Harness（DSH）开发的 **AI 原生 DevOps 流水线工作台** —— 形态上对标 GitLab CI / 腾讯蓝盾，核心差异是**与 AI 会话深度联动**。

**差异化设计**（立项即明确）：

| 维度 | 传统 DevOps | dsh-devops |
|---|---|---|
| 写流水线 | 人手写 YAML | 对 AI 说需求，AI 按技能规范生成可直接保存的配置 |
| AI 的角色 | 无 | 技能给规范 + 工具给写权限 + 校验回环让 AI 自我修正 |
| 界面与 AI | 割裂 | 界面可「让 AI 帮我写」，也能把失败日志交给 AI 解释 |
| 安全边界 | — | AI 可创建/修改流水线，但**触发运行必须用户明确要求** |

**交付形态**：DSH 宿主插件（`index.js` 导出 `apply(ctx, config)`）+ 手写单文件前端（`client.js`，零构建）。

## 二、设计阶段

### 2.1 先做能力取证，不凭想象设计

设计第一步是把宿主真实能力摸清，逐项读源码确认**哪些能复用、哪些必须自研**：

| 能力 | 取证结论 |
|---|---|
| 进程执行 | `ctx.subprocess.spawn()` 可复用；collect 模式的 `readFrom(fromByte)` 与 jobs 输出源字段级同构 |
| HTTP / SSE | `ctx.webServer.register({kind:'prefix'|'exact', path, handler})`，handler 是原生 `(req,res)`，**明文允许挂住响应做 SSE**；`text/event-stream` 已被宿主跳过 gzip |
| 持久化 | `ctx.storageDomain.open(spec)` 提供原子写 + 版本号 + 变更事件 |
| 密钥 | `ctx.credentials` 只存**引用名**，值由 provider 持有 |
| 技能注册 | `ctx.skills.register({name, description, content, resourceBase})` |
| 会话联动 | `agent.inject()`（不唤醒）/ `followup()`（唤醒）/ `ctx.agents.get(sessionId)`；前端 `ctx.uiWorkspace.startSession({prompt})` |
| 前端插件 | **手写单文件** `window.__ModuleLoader__.load({id, factory})`，`require('react')` 由宿主 module table 提供，**无需打包器** |

**据此划定了三块"不自研"**：执行器、持久化、HTTP/SSE 通道 —— 直接复用宿主能力。**同时确认三块"必须自研"**：CI 语义模型、DAG 调度器、远端 SSH 传输（宿主无 SSH seam）。

### 2.2 关键技术选型

| 决策点 | 选择 | 理由 |
|---|---|---|
| SSH 传输 | 依赖 `ssh2`（可选、惰性加载） | 系统 `ssh.exe` 在 Windows 下密码认证不可靠；`ssh2` 能可靠拿流、做 SFTP、精确取消 |
| glob 匹配 | **自研零依赖** | 避免依赖树；且需与远端语义完全一致 |
| 文件锁 | **自研**（`mkdir` 独占） | 只需跨进程互斥一件事 |
| 前端构建 | **手写拼接脚本**，产物入库 | 装包即用；宿主白名单限制下本来也用不了第三方库 |
| 数据持久化 | 文件后端（原子替换）+ 可选 storageDomain | 零依赖优先 |
| 不采用现成 SSH 插件 | 参考其实现但**不依赖** | 它通过替换单槽 `ctx.subprocess`/`ctx.fs` 工作，一次只能接管**一台**主机 —— 与「多服务器并存、逐步骤选服务器」冲突 |

### 2.3 冻结接口契约（关键组织决策）

在写任何实现代码前，先产出 **`docs/CONTRACT.md`（394 行）** 作为唯一接口权威：

- 数据模型 JSON 形状（Pipeline / Template / Server / Run / Step / 资源库）
- 每个模块的导出签名（§3.1–3.13）
- 字段类型 → 前端控件映射表（15 种类型）
- 安全约定（强制条款）
- **写入范围划分**（每个角色只能改哪些文件）

**为什么先做这件事**：6 个角色要并行写入，没有冻结的契约必然互相踩踏。

### 2.4 开发组织

```
lead            包骨架、元数据、装配协调、端到端验收、最终复核
host-core       模型 / 校验 / 变量合并 / glob / Store / 模板 / 资源库
engine          DAG / RunEngine / 18 节点 / 本地执行器 / 日志存储
remote          SSH 执行器 / provisioner / 远端浏览
api-tools       HTTP 路由 / SSE / 10 个 Agent 工具 / 技能注册 / 装配
client-ui       整页工作台 / 状态栏 / 编辑器 / 类型化控件 / 日志面板 / AI 入口
verifier        测试套件与文档
```

**协作纪律**：按契约签名编程、不越界改文件、完成后自证并报告；Lead 独立做端到端验收。

## 三、开发阶段

### 3.1 v0.1.0 —— 从零到可运行

**宿主侧**
- `index.js` 装配：store → logstore → nodeRegistry → provisioner → executors → engine → 路由 → 工具 → 技能 → `/devops` 命令；所有宿主注册挂 `ctx.effect()`（热重载可摘除）。
- **52 条 HTTP 路由**：流水线/模板/运行/服务器/资源库/节点/文件浏览/导出导入/设置，统一 `{ok,value}` / `{ok,message}` 响应，body 上限 1MiB，默认仅 loopback。
- **SSE 协议**：`run` / `step` / `log` / `gap` / `ping` 五类事件，`Last-Event-ID` 断线续传。
- **10 个 Agent 工具**：列出/创建/更新/校验/运行/查状态/读日志/取消/查服务器/装环境；每个都带 `output.schema` + `render`。只读工具声明并发安全，写入类保持独占。
- **技能注册**：`devops-pipeline-authoring`，把流水线规范、18 个节点的完整参数表、变量优先级、常见失败写进正文。

**执行引擎**
- **两种调度模式**：有 `needs` 走 DAG，否则阶段串行 + 阶段内并行；混用被校验拒绝（明确无歧义）。
- 失败传播 / `allowFailure` / `when`（on_success/always/manual）/ 重试退避 / 超时 / 取消（三段式：signal → terminate → 等 `waitForExit`）。
- **执行位置由地址决定**：`127.0.0.1`/`localhost`/`::1`/本机主机名 → 本地；其它 → SSH。两种执行器共享同一契约，**节点与引擎代码不区分本地/远端**，日志格式完全一致。
- 子流水线调用（`pipeline.call`）含引用环检测与深度限制。

**环境供给（provisioner）**
- 连接后自动探测：OS/发行版、shell、工作目录、已装运行时、可用包管理器、`sudo` 是否免密。
- 按需安装/切换：Python 优先 `uv` → `pyenv` → 发行版包；Node 优先 `nvm`/`fnm`/`mise`。
- **默认不擅自安装**（`allowInstall=false`）：缺环境时步骤失败并给出可一键执行的建议。

**节点系统**
- **18 个内置节点 / 7 个分类**：执行（shell/node/python）、文件（pick/write/copy/artifact）、缓存（save/restore）、流程（condition/wait.delay/wait.approval/pipeline.call）、环境（ensureRuntime）、网络（http/webhook）、通用（log/env.set）。
- **101 个字段描述符**、15 种字段类型驱动前端控件 —— **新增节点无需改前端**。
- 自定义节点：界面内创建，落盘为数据目录内 `.mjs`，默认禁用（需显式开启）。

**前端**
- 三槽成对注册：`main`（keyed，`key='devops'`）+ `sidebar.panellist`（list，`id='devops'`）+ `shell.overlay`（状态栏）。
- **8 页工作台**：概览 / 流水线 / 模板 / 运行 / 服务器 / 资源库 / 节点库 / 设置。
- 运行详情：步骤卡片可点开看 **SSE 实时日志**（自动滚动、暂停跟随、过滤、下载）。
- **卡住诊断**：7 段 phase 流转（queued→connecting→provisioning→transferring→running→draining→settled）+「已多久无输出」+ 超时倒计时 + 失败归因。
- 类型化控件：目录/文件选择器（可浏览校验）、glob（**实时命中预览**）、运行时版本（含一键安装）、服务器选择器、键值对、引用选择器。

**验收**：测试 **326 条全绿**；HTTP 端到端 **20/20 通过**（8 步流水线全 success、插值正确、三语言日志回传、`file.pick` 命中 85 文件、SSE 帧正常、导出无密钥明文）。

### 3.2 v0.2.0 —— 编排工作台重做

对编排界面做了**一次完整的交互重构**：

**画布与编辑**
- 画布改**横向布局**：阶段成列、节点为块状卡片；列头/列间/画布末尾三处都能就地插入新阶段（含并行开关）；`needs` 依赖边按列布局重算走线（forward / vertical / backward 三种）。
- 节点编辑改为**覆盖画布的编辑浮层**：点节点浮出、背景虚化；**点浮层外部即自动保存并收起**，Esc 同样关闭；宽度可拖拽并记住。
- 流水线**详情页**与编辑器同构但只读；点节点从右侧滑出**圆角悬浮抽屉**，内部可在「节点信息 / 日志」间切换。
- 状态色体系：卡片/列头/列表行/状态点按 running/success/failed/canceled/pending 着色，运行中带呼吸动效（尊重 `prefers-reduced-motion`）。

**SSH 认证与互操作**
- **私钥支持选择本机文件**：`auth.keyPath` → 凭据引用 → `keyRef` 为路径 → 插件配置，四级优先级；路径不存在/是目录/超限（>1MB）都有稳定错误码；私钥内容只进打码列表、**绝不落日志**。
- 新增字段类型 **`ref:pipeline`**：`pipeline.call` 的子流水线改为可搜索下拉，按名字/ID/描述模糊匹配、命中高亮、允许手填。

**可观测性**
- 日志面板改**深色终端观感**（固定深色底、等宽字体、`tab-size:2`）。
- 新增**共享语法着色引擎**（零依赖纯函数）：识别 shell/python/javascript/json/yaml，10 类 token 由 CSS 调色板着色；日志与代码编辑器共用。
- 代码编辑器升级为「着色层 + 透明 textarea 叠加」：语法高亮、行号、自动增高、一键全屏。
- 运行创建时保存**流水线定义快照** → **编辑流水线不再影响已运行/运行中的运行**。
- 离开界面再回来**保留视图状态**（页签、编辑中的流水线、选中节点、筛选），按 id 重新取数据避免陈旧。

**验收**：测试从 328 增至 **610 条，全部通过**。

### 4.2 安全

- 所有命令以 **argv 传递**，用户输入绝不拼进 shell 命令行。
- 密钥只从凭证服务解析；日志 / SSE / 工具输出 / 导出**在写盘前打码**。
- 路径访问做 **realpath containment** 校验；HTTP 路由默认仅 loopback。
- 自定义节点与导入代码默认禁用；`kind:'ssh'` 禁止 `auth.type:'none'`（防静默无认证连接）。

### 4.3 工程

- 纯 ESM、**零构建**、除可选 `ssh2` 外**零运行时依赖**。

## 六、关键设计决策

1. **AI 能改但不能自动跑** —— AI 可创建/修改流水线，触发运行必须用户明确要求，避免"AI 误跑生产部署"。
2. **默认不擅自改远端系统** —— provisioner 缺环境时默认失败 + 给建议，只有显式 `allowProvision` 才自动安装。
3. **两种调度模式互斥** —— 有 `needs` 走 DAG，否则阶段模式，混用直接校验拒绝。宁可报错也不留歧义。
4. **执行位置由地址决定** —— 用户不需选"本地/远端"，填 `127.0.0.1` 在本地跑，填云服务器地址走 SSH。
5. **执行器统一契约** —— 节点与引擎代码完全不区分本地/远端，显著降低双路径维护成本。
6. **未定义占位符直接报错** —— 不静默留空，宁可配置失败也不生成"看起来跑了其实参数丢了"的流水线。
7. **前端不引第三方库** —— 受宿主白名单限制，换来零构建、单文件、装包即用（编辑器/画布/代码高亮全部自研）。

## 七、AI 原生的落地形态

这是与传统 DevOps 最大的区别，由三条机制组合实现：

**① 技能给规范** —— 随包提供 `devops-pipeline-authoring` 技能，正文包含：
- 完整流水线 JSON 形状与硬约束（不得混用 needs 与 parallel）
- **18 个节点的权威参数表**（由真实节点描述符生成）
- 变量优先级心智模型、7 种占位符用法
- 常见失败与含义对照表
- 产出前自检清单

**② 工具给写权限** —— 10 个工具让 AI 的产出**真正落库生效**，而非只打印文本。

**③ 校验回环** —— AI 提交的定义先过校验，失败时返回结构化错误（字段路径 + 原因 + 怎么改），AI 可自我修正直至通过。

**一条关键经验**：技能文档里的参数表**必须与实现同源生成**。手写极易产生参数名漂移（如 `cwd` 与 `workdir`、`expression` 与 `condition`），而错误的参数名不会报错、只会被静默忽略 —— AI 会稳定地生成错配置。改为从真实描述符生成后彻底解决。

## 八、可复用的方法论

1. **先取证再设计** —— 把平台真实能力逐项读源码确认，划清"能复用"与"必须自研"的边界。本项目因此避免了自研执行器、持久化、HTTP/SSE 通道三块大工程。
2. **冻结接口契约再并行** —— 契约先于实现，且包含写入范围划分。这是 6 角色能并行而不互相踩踏的前提。
3. **Lead 必须独立端到端验收** —— 单测全绿 ≠ 能用；集成期才会暴露的问题只能靠真实环境验证。
4. **回归测试要注入缺陷验证** —— 否则无法确认它真的能抓到问题。
5. **区分"测试期望错"与"实现错"** —— 遇到失败先判断是断言假设不对还是实现真有缺陷，不为变绿而放宽断言。
6. **同进程开发注意模块世代** —— 装完插件需禁用再启用（或重启宿主）才会加载新代码。
